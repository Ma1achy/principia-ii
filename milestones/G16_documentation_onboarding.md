## Goal

Principia has a deep spec, seven ratified ADRs, five-plus skills, and a full
milestone series — but had **no user- or contributor-facing documentation**.
G16 synthesises the existing artifacts into a `docs/` site: a **user guide**,
an **architecture guide** (pointing at the skills, not duplicating them), an
**ADR index** that links and explains the ratified contracts, a **"how to add
a new chart" runbook** (the canonical `(Y, Φ)`-only extension path), a
**glossary**, and a **TypeDoc** API-doc setup. None of this prose can drift
silently, so G16 ships a **pure docs-completeness/link checker** as its gate:
every milestone in `milestones/README.md` and every ADR in `docs/adr/` must
be linked from the docs index, every glossary term must be non-empty, and
every intra-doc relative link must resolve to a real file.

**Exit criterion (single executable test).**

```bash
npm test -- --run test/unit/docs/completeness
```

passes with at least **18 green tests** (18 as landed): the docs index links
every milestone listed in `milestones/README.md` (all 32 — M0–M12 and
G1–G19); the ADR index links every `docs/adr/NNNN-*.md`; every required
`docs/` page exists and is linked from the index; every glossary term has a
non-empty definition; and every intra-doc relative link resolves on disk. No
GPU, no browser, no network.

**Deliverable:** a browsable `docs/` site — user guide, architecture guide,
ADR index, "add a new chart" runbook, glossary, and a TypeDoc API-doc setup
(`npm run docs:api` → `docs/api/`, gitignored) — with the pure
docs-completeness/link checker as its gate.

## Reconciliations against the landed codebase

1. **The doc's index listed 29 milestones; the real index has 32.** G17
   (debug harness), G18 (debug HUD), and G19 (regularization) postdate the
   G16 draft. `checkMilestoneCoverage` reads `milestones/README.md` at check
   time, so the docs index links all 32 — and the next new milestone will
   fail the gate until it is linked (self-enforcing, as designed).
2. **The doc's render-mode table was fiction.** It listed Outcome / vMF /
   Diffusion / FTLE / Coherence as "render modes" — but the landed surface
   (M7, `src/render/types.ts`) is 23 **colour modes** × 5 **brightness
   modes** × 3 **combiners** × 9 palettes × 5 CVD modes. There is no FTLE or
   coherence colour mode, and diffusion is a *brightness* mode. The user
   guide documents the real groups.
3. **Keyboard table corrected to the landed bindings.** Zoom-in is `=` (not
   `+`/`=`); `Escape` dismisses an overlay first and falls through to unlock
   (G13's boolean OverlayHooks); the `~` dev-HUD toggle (G18) is included.
4. **Spelling: Broucke–Hénon.** The draft wrote "Brouke–Hénon"; the
   physicist is Roger Broucke. The glossary term and manifest use the
   correct spelling.
5. **Chart table uses the landed `ChartId`s** (`latent_slice`, `lz_e`,
   `lz_k`, `shape_sphere`, `mass_simplex`, `burrau_euclid`, + the mixed
   factory) and the runbook points at the real registration surface
   (`src/chart_atlas/index.ts`, `chartUniforms(view)` per G4, descriptor
   constructors from `@/decode/pipeline.js` per M10).
6. **The docs index also links the existing project records** (ledger,
   test-and-ci-strategy, integrity-pass) — the link checker walks *every*
   `.md` under `docs/` (except `api/`), so those pages' links are now gated
   too (they were verified clean before landing).

## Key surfaces

- **`src/docs/manifest.ts`** — `DOCS_MANIFEST` (index, 5 required pages, ADR
  index page, glossary page, 11 glossary terms), `DEFAULT_LAYOUT`,
  `normaliseTerm`. The milestone and ADR sets are *read from disk* at check
  time, never hard-coded.
- **`src/docs/completeness.ts`** — pure: `parseLinks` (inline links, images
  excluded, code stripped first), `isExternal` / `stripAnchor` /
  `relativeLinkTargets`, `checkIndexLinksPages`, `checkMilestoneCoverage`,
  `checkAdrCoverage`, `checkGlossaryTerms` (+ `parseHeadingSections`),
  `checkRelativeLinks` with `posixResolve` that **preserves leading `..`**
  so links escaping `docs/` (e.g. `../milestones/*.md`, `../CLAUDE.md`)
  resolve against the repo root instead of silently no-opping.
- **`test/unit/docs/completeness.test.ts`** — a thin loader reads the real
  docs; 18 tests: parser (4), path resolution (2), headings (2), index↔pages
  (2), index↔milestones (2), ADR coverage (1), glossary (3 incl. two
  negative controls), link resolution (2 incl. a negative control).

## Notes for the implementer

- **The manifest is the single source of truth.** Required pages and glossary
  terms live in `src/docs/manifest.ts`; the milestone and ADR sets are read
  from disk at check time — that is what makes "add a milestone → add a docs
  link" self-enforcing.
- **The checker is pure; only the test does I/O.** `completeness.ts` takes
  contents and an `exists` predicate; the negative controls run entirely
  in-memory while the gate verifies the shipped pages.
- **Don't duplicate the skills.** The architecture guide is a *map* into
  `.claude/skills/` — it names the seam and points at the skill. Prose
  drifts; the skill is maintained.
- **Keep render-only vs compute-affecting straight in the prose.** The user
  guide and architecture page agree with M7/G12/G13: colour/brightness/
  combiner/palette/CVD are render-only (64-byte group-3 rebind, no history);
  chart/view/mass/tier changes recompute.
- **TypeDoc is out-of-gate on purpose.** It emits HTML that would make the
  link checker noisy, so `docs/api/` is gitignored and excluded from the
  page walk. Run it locally or in a separate CI job.
- **Link style the checker understands.** Inline `[text](relative/path.md)`
  with POSIX separators; anchors are stripped before resolution.
  Reference-style links and bare angle-bracket URLs are not parsed — keep
  intra-doc links inline so coverage is detected.
